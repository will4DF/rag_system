List and details of the individual permissions that are assigned to system and custom permission groups.

# Overview

This article details each of the permissions offered in Element451. These permissions are automatically added to [System Permission Groups](https://help.element451.com/en/articles/2735389-permission-groups-overview#h_7d10032f10) and cannot be edited. You can, however, add these permissions to [Custom Permission Groups](https://help.element451.com/en/articles/9020578-creating-managing-custom-permission-groups) and assign users to those Permission Groups to tailor access to your specific needs.

## Accessing Permissions

These permissions are accessed when viewing system groups or creating/editing custom groups. Navigate to your profile picture in the top right corner, then click **Settings** > **Manage** **Users** > **Permission** **Groups**. Once you're on the Permission Groups page, you can view and edit individual permissions by clicking on a specific group. Keep in mind that permissions within system groups cannot be modified.

**\*Additional Info: Sensitive Info Redacted**

When a user has the **See Sent Email/SMS Content – Sensitive Info Redacted** permission, they can view sent message content in a student's activity history, but certain sensitive values are automatically hidden before the message is displayed.

**What gets redacted:**

* Temporary passwords
* Magic login links and one-click authentication links
* Authentication or access tokens embedded in URLs
* Social Security Numbers
* Other values that could allow someone to log into a student account or access private systems

**What is NOT redacted**: Personal information that already appears on the student's profile — such as name, email, or phone number — is not redacted, since the user is already authorized to view that information.

**How it works**: Element451 automatically scans sent message content (email and SMS) and detects patterns associated with sensitive credentials or secure login URLs. When detected, those values are replaced with a redacted placeholder before the message is displayed.

Users with full (non-redacted) permissions will see the message exactly as it was sent. Users with this redacted permission will see the same message with sensitive values removed.
